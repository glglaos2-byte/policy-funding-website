# 주말 연결 작업

## 현재 구현
순수 HTML/CSS/JavaScript. 빌드, npm 설치, API 키 없이 실행됩니다. 외부 폰트·이미지 요청도 없습니다.
- index.html: 메인
- information.html: 검색·분류·제도 가이드·공식 공고 링크·FAQ
- consultation.html: 브라우저 필수값 검증. 실제 전송/저장 없음
- admin.html: 템플릿 초안 생성, 편집, localStorage 최대 30개 저장·불러오기·삭제, txt 다운로드. 실제 AI·인증·발행 없음

## 서버 연결 시
1. 임시 브랜드 ‘바른자금’을 실제 상호·로고·사업자 정보로 교체하고 표시 콘텐츠 검토.
2. HTTPS 호스팅과 실제 도메인 결정. 각 공개 페이지에 그 주소의 canonical·og:url·공유 이미지 추가. 실제 URL을 넣은 sitemap.xml 작성 후 robots.txt에 Sitemap 주소 추가.
3. 네이버 서치어드바이저·Google Search Console 소유 확인과 사이트맵 제출. 지금은 페이지별 title/description/OG, 한국어 lang, 의미 있는 HTML, FAQ JSON-LD, 관리자 noindex 적용. ChatGPT 등의 검색 노출은 보장되지 않으며 llms.txt도 노출 보장이 아님.
4. 상담 POST API, 입력 서버 검증, 개인정보 수집 목적·항목·보유기간·동의, 접근권한·보관·삭제 정책, 스팸 방어를 구현. 실제 동의 문구와 접수 성공/실패 UI로 변경. 개인정보는 로그나 브라우저 저장소에 보관하지 않기.
5. 관리자 서버 인증·인가 필수. noindex는 접근 제어가 아님. AI API 키는 서버에서만 관리. 요청 제한·비용 제한·오류 처리·공식 출처 확인·사람의 검토 후 발행 단계를 구현.
6. 기사 데이터 저장소와 개별 Article 페이지 연결. 실제 저자·작성일·수정일·출처로 Article 구조화 데이터를 구성하고 사이트맵 갱신. localStorage 초안을 서버로 자동 전송하지 않기.
7. 운영 전 키보드·스크린리더 접근성, 실제 기기, 개인정보 흐름, API 오류·권한, 검색엔진 수집을 다시 검증.

## 현재 확인 결과
시스템 Chromium + Playwright로 1440/390/320px × 네 페이지의 가로 넘침 없음, 페이지별 h1, 정보 검색/필터/빈 결과, 상담 폼 작성과 데모 완료, 기사 생성·저장·새로고침 후 복원·불러오기·다운로드·삭제 확인. JS 런타임 오류 없음. 실제 서버 접수·AI API·검색 노출은 검증 대상이 아님.
